# Surface: console (SentinelLM policy/audit/metrics console)

**Scope:** `console/` — the whole React app (Policies, Audit, Metrics routes). Mode: **Operate**.

**Audience & job:** Two overlapping readers. (1) A technical evaluator (confirmed: Apple-caliber technical interviewer) who opens this once, for a couple of minutes, and forms an impression of engineering + design craft from feel and behavior alone. (2) The security/platform engineer persona the tool is truthfully built for, who would author policy, search audit history, and watch live decision metrics as a recurring task. Design for (2)'s real task shape; (1) is who actually shows up first and whose few minutes matter most.

**Action/task:** Create/edit/enable/dry-run a policy rule and see it take effect; filter and page through an audit log; read live request/decision/latency metrics.

**Proof/content:** All content is real, not mocked — real seeded policies, real audit records generated by real detector runs, real Prometheus-style stats. Nothing here should look like placeholder demo data; every number the console shows is a number the gateway actually produced.

**Constraints:** Must never obscure the task: policy table, audit table, and metrics must stay scannable at information density, per the user's explicit "wrong = either generic sameness or decoration that fights density, both equally unacceptable." Existing REST contract (`/api/v1/policies`, `/api/v1/audit`, `/api/v1/stats/*`) and all current behavior (optimistic toggle, cursor pagination, dry-run, URL-synced filters) are fixed; only the visual language changes. Accessibility: standard web a11y, no stated additional requirement.

## Chosen direction: "The Instrument Room"

A seismograph/polygraph paper-tape recorder, translated into a live security console. Rejected up front: (a) the generic indigo/slate SaaS-admin look this project already had — the category rut; (b) a green-phosphor hacker-terminal aesthetic — the predictable "security tool" cliché, and one of new-work's own named AI-cluster traps.

- **World:** warm paper-toned ground with real tactile grain, not a flat tint (not stark white, not slate-gray), precise black ink-trace linework as the primary graphic language. One accent ink reserved for BLOCK-severity (a confident, saturated vermillion/sienna — a fresh stamp-pad ink, not a dusty one), a second confident ochre/amber for MASK-severity; ALLOW stays calm graphite/black. Restrained *strategy* (two inks, used rarely) — not restrained *saturation*: the inks earn their rarity by having real punch when they appear.
- **Type:** a real geometric mono (IBM Plex Mono or equivalent) as the instrument/data voice for everything numeric — timestamps, latencies, entity types, IDs — evoking a strip-chart's printed calibration marks. Plain system-UI sans (`-apple-system` stack) for chrome and labels — deliberately workhorse, and a quiet nod to the Apple-evaluator register rather than an imported "friendly SaaS" display face.
- **Signature components:** decision badges render as ink-stamped marks, not rounded pills. Detected spans in the dry-run/audit text get circled/underlined in their severity ink, like a technician marking an anomaly. Metrics timeseries charts are literal instrument traces on a fine ruled calibration grid, not default Recharts styling — spikes read as a needle jumping.
- **Memorable moment (post-critique: allowed to be theatrical, not just tasteful):** pressing "Test" in the dry-run panel visibly draws a live trace across a mini recorder strip and lands on a hard ink-stamped ALLOW/MASK/BLOCK mark, with a brief press-down/settle weight to the landing — the one moment in the system allowed a shadow beyond the overlay exception, because it's the signature moment this whole direction exists to earn.
- **One kinetic tell at rest:** the channel strip carries a small live "recording" pulse (ink-colored, not a severity color) so the shell reads as an instrument actively running, not a static frame — the only motion happening outside of direct interaction.
- **Dark mode:** reads as "the same instrument under night-shift lighting" — warm dark, same texture, not a neon-on-black palette swap.

## Unresolved

- Exact ink hex values, calibration-grid spacing, paper-texture technique (CSS noise/SVG grain/image), and stamp/mark component construction are implementation decisions for the build pass, not fixed here.
- Whether the "trace" motif extends to the Audit page's row-hover/selection state (not yet decided) — treat as an open question for whoever builds this.
- DESIGN.md is intentionally a **seed** (directional, no real tokens yet) until this direction is actually implemented in code; re-run `$impeccable document` after the build to capture real values and generate the component sidecar.
